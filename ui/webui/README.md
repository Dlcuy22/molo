# molo webui

The Wails v3 desktop front end for the molo engine. It is the second UI in
this repository; `ui/tui` is the terminal one. Both talk to the engine through
the same facade, `github.com/dlcuy22/molo`, and share no UI code.

## What it is

A Go backend that owns one `molo.Player` and exposes its cheap commands as
bound methods, plus a Svelte 5 frontend that renders them. Wails embeds the
built frontend in the binary, so the shipping artifact is one native window with
no server and no ports.

The Go side holds no audio logic. It adapts:

- Reads the engine's sealed event channel on a goroutine and re-emits each
  change as one `molo:snapshot` payload, so the frontend has a single
  subscription instead of a poll per field.
- Polls the position at 4 Hz and folds it into the same payload, because the
  engine reports discrete changes as events but the playing position moves
  continuously.
- Runs a spectrum pump at 60 Hz over the engine's `Tap`, so the visualizer never
  reads the audio path from the UI thread.
- Resolves files and folders to a queue, the same way the TUI reads its
  arguments.
- Indexes the tags of every queued track through the engine's own meta chain, so
  the quick-open palette can search by title, artist and album. The index is
  built off the control path and cached by path; a replaced queue drops what
  left it.
- Runs previews on a second player over the same audio context, so the main
  track stays loaded and paused underneath and resumes instantly. The fade is a
  real dsp effect (`dsp/fade.go`), not a volume ramp, because the master gain
  applies once per buffer and would click.

## Layout

```
main.go                     application entry, window, file-drop listener
playerservice.go            the bound service: molo.Player to the bridge
codec.go                    decoder label formatting for the chooser
playerservice_test.go       queue expansion and payload mapping
internal/spectrum/          FFT and band reduction for the visualizer
internal/cover/             artwork decoding and thumbnail scaling
frontend/src/app.css        design tokens from DESIGN.md, once
frontend/src/lib/store.ts   the one subscription to the bridge
frontend/src/lib/format.ts  clock and name helpers
frontend/src/lib/search.ts  quick-open matching over the queue tags
frontend/src/lib/components/  Transport, TrackInfo, Queue, Spectrum, Controls, CommandPalette
frontend/bindings/          generated by wails3; never edited by hand
```

## Features

- Add files or a folder, by picker or by dropping onto the window.
- Transport: play/pause, previous, next, stop, seek, volume and mute.
- Queue list; clicking a row plays it (`PlayIndex`).
- Quick open: Ctrl+P (Cmd+P on macOS) or the Search button opens a palette over
  the queue. It matches title, artist, album and file name. Arrow keys move,
  Enter plays, Escape closes. Album art loads lazily, only for the rows actually
  on screen, so a large queue never decodes art the user has not scrolled to.
- Preview: Ctrl+Alt+P (or the Preview button) auditions the highlighted row on a
  second output while the main track pauses. Moving the selection fades the old
  window out and the new one in; the window loops until you move. Ctrl+Alt+L
  toggles looping. The main track resumes when preview mode ends (toggle off,
  palette close, or Enter). Window start, length, fade and volume are editable in
  the palette's settings panel.
- Preview positioning is gated: the second player's output is held silent by a
  zero-length fade-out while the engine's asynchronous seek lands, so a non-zero
  "start at" never lets the head of the track be heard first.
- Now-playing row with album artwork when the file carries it; a muted music
  note stands in when it does not.
- Decoder and output backend selection, applied to the live track.
- A bar visualizer: 150 points by default over 20 Hz to 20 kHz, 3.8px rounded
  bars, dynamic range tracking the loudest recent content. The point count and
  the frequency range are adjustable.

## Running

```sh
bun install --cwd frontend     # once
wails3 dev                     # hot reload, opens a window
wails3 build                   # bin/molo
```

There is no GUI in a headless container, but the app also builds in server
mode, which serves the same frontend over HTTP:

```sh
go build -tags "server,production" -o bin/molo-server .
./bin/molo-server            # http://127.0.0.1:18080
```

Server mode is how this UI was verified without a display: a browser drives the
page while the Go methods are called over the same bridge the window uses.

## Notes

- Dark only, by the owner's decision in `DESIGN.md`. There is no theme toggle,
  so there is no second mode to keep in sync.
- The accent `#3584e4` measures 4.46:1 on the background, just under WCAG AA for
  normal text, so it is used for fills and large controls, never small text.
- Bindings are generated from the Go service. After changing a bound method or a
  payload type, run `wails3 generate bindings -ts -d frontend/bindings` and
  re-run `bun run check`.
